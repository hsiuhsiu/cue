# Cue 0.4.0 — Personalized search and launch at login / 個人化搜尋與登入時啟動

## English

Cue 0.4.0 learns your launcher choices, adds optional launch at login, and simplifies building and installing your own copy.

- **Personalized search:** within the same matching category, Cue prefers what you usually choose for that query, then overall frequency weighted toward recent use. Older usage loses half its weight every 14 days. Exact matches remain ahead of weaker matches; matching commands remain before apps. Only successful app launches and commands count—typing, selection, cancellation, failures, and searches inside Clipboard History do not.
- **Responsive input:** search reads precomputed memory scores; loading, calculation, and saving run in the background. New learning takes effect on another query or invocation, keeping visible rows and numbered shortcuts stable. Sorting avoids repeatedly copying application data.
- **Launch at login:** enable **Command+, → Startup → Launch at login**. New installations start off; existing macOS registration is reflected. If approval is needed, use **Open Login Items…** and allow Cue in System Settings. Disable it in Cue or macOS, and keep the same installed app location when updating.
- **Local learning:** successful queries, app paths or command identifiers, scores, and timestamps stay in readable, unencrypted JSON on this Mac; nothing is uploaded. Limits are 512 results, 256 queries, and eight associations per query. Clipboard contents are excluded. Quit Cue and remove `~/Library/Application Support/com.yyhsiu.cue/Search/usage.json` to reset learning without removing settings or clipboard history.

Optimized synthetic testing with 1,000 apps and full learning history measured core search p95 at **0.930 ms**, versus **0.931 ms** before learning. These component timings exclude input delivery, drawing, icons, and app launching. Both versions had occasional long wall-time samples, much of which was off the measured thread's CPU; this is not a guarantee of end-to-end latency. See the [performance report](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/performance-adaptive-search.md).

### Install or upgrade

[Download Cue 0.4.0](https://github.com/hsiuhsiu/cue/releases/download/v0.4.0/Cue-0.4.0-universal.dmg) · [Checksums](https://github.com/hsiuhsiu/cue/releases/download/v0.4.0/SHA256SUMS.txt)

Choose **Check for Updates… → Install and Relaunch** in Cue, or quit Cue, open the DMG, and drag **Cue.app** into **Applications**, replacing the old copy. Open the installed app; it lives in the menu bar, with **Option+Space** as its default shortcut. Settings, clipboard history, and learning are preserved. Automatic update checks are optional; you choose when to install and restart. Self-updating requires a writable installed location, not the read-only DMG.

To build your own copy, install full **Xcode with Swift 6 or later**, open it, and finish its license and setup, including after upgrades when requested. Command Line Tools alone are insufficient. The workflow was tested with **Xcode 27**; the first build needs internet access for the pinned Sparkle dependency. Quit any running Cue, then run:

```sh
git clone https://github.com/hsiuhsiu/cue.git
cd cue
./scripts/install-app.sh
open "$HOME/Applications/Cue.app"
```

This verifies and permanently installs an optimized Release app for your Mac at `~/Applications/Cue.app`, preserving existing data, without a paid developer account, signing key, or administrator access. The installer refuses to replace a running Cue and verifies a staged copy first. For later source updates, quit Cue and run `git pull --ff-only` and `./scripts/install-app.sh`. To stay on your own builds, disable automatic update checks; an update offered by Cue replaces your build with the published app and does not compile your repository. See the [source installation guide](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/building.md).

The app is ad hoc-signed, **without Developer ID signing or Apple notarization**. Sparkle verifies signed update archives and feeds; this does not replace Apple's first-launch checks. If blocked, follow the app-specific steps in the [installation guide](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/installation.md).

Validation includes optimized automated core, persistence, launcher, keyboard, clipboard, settings, login-item, localization, and system-command checks, plus manual launcher use. Tests use synthetic data and injected system actions; the Mac was not actually put to sleep or locked. Login registration/status were checked, but an actual logout/reboot startup cycle and a public update installation on a second Mac remain unverified. Lock Screen uses a private macOS service that may require future changes. The universal app targets **macOS 14+** on Apple silicon and Intel; this release was built with **Xcode 27** and runtime-tested only on **Apple silicon / macOS 27.0**.

## 正體中文

Cue 0.4.0 會學習你在啟動器中的選擇，加入可選擇的登入時啟動，並簡化自行建置與安裝的流程。

- **個人化搜尋：**同一符合程度內，先考慮該關鍵字通常選擇的項目，再參考帶有近期加權的整體使用頻率。舊記錄的權重每 14 天減半。完全符合仍優先於較弱的符合結果，符合的指令仍排列在 App 前方。只有成功開啟 App 或執行指令才算；打字、移動選取、取消、失敗及剪貼簿頁面的搜尋都不記錄。
- **維持即時操作：**搜尋讀取記憶體中預先計算的分數，載入、計算與儲存都在背景執行。新的學習結果等下一次查詢或叫出 Cue 才採用，避免正在選擇時列表與編號快速鍵跳動。排序也減少反覆複製 App 資料的成本。
- **登入時啟動：**在 **Command+, → 啟動 → 登入時啟動** 開啟。新安裝預設關閉，並反映 macOS 既有的註冊狀態。需要授權時，按**開啟登入項目⋯**，再到系統設定允許 Cue。可從 Cue 或 macOS 關閉，更新時請維持相同安裝位置。
- **本機學習資料：**成功操作的關鍵字、App 路徑或指令識別碼、分數與時間，以可讀、未另外加密的 JSON 保存在這台 Mac，不會上傳。上限為 512 個結果、256 個關鍵字，每個關鍵字八個結果關聯，不包含剪貼簿內容。若要重設，先結束 Cue，再刪除 `~/Library/Application Support/com.yyhsiu.cue/Search/usage.json`，不影響設定或剪貼簿記錄。

以最佳化版本、1,000 個合成 App 與滿容量學習記錄測試，核心搜尋 p95 為 **0.930 ms**，加入學習前為 **0.931 ms**。這些元件耗時不包含按鍵傳遞、繪圖、圖示與 App 啟動。兩個版本都曾出現偶發的較長經過時間，其中許多時間並非該執行緒正在使用 CPU；這不代表端到端延遲保證。詳見[效能報告](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/performance-adaptive-search.md)。

### 安裝或升級

[下載 Cue 0.4.0](https://github.com/hsiuhsiu/cue/releases/download/v0.4.0/Cue-0.4.0-universal.dmg) · [檢查碼](https://github.com/hsiuhsiu/cue/releases/download/v0.4.0/SHA256SUMS.txt)

從 Cue 選擇**檢查更新⋯ → 安裝與重新啟動**；或先結束 Cue，開啟 DMG，將 **Cue.app** 拖進**應用程式**取代舊版本，再開啟已安裝的 App。Cue 位於選單列，預設快速鍵為 **Option+Space**。設定、剪貼簿記錄與學習資料會保留。自動檢查可以關閉，安裝與重啟由你決定。自我更新需要已安裝且可寫入的位置，不能直接從唯讀 DMG 執行。

自行建置需要內含 **Swift 6 以上的完整 Xcode**；請先開啟並完成授權與設定，升級後若再次要求也需完成。只有 Command Line Tools 無法建置。此流程已在 **Xcode 27** 測試，首次建置需要網路下載固定版本的 Sparkle 相依套件。先結束正在執行的 Cue，再執行：

```sh
git clone https://github.com/hsiuhsiu/cue.git
cd cue
./scripts/install-app.sh
open "$HOME/Applications/Cue.app"
```

此流程會驗證並將適合這台 Mac 的最佳化 Release 版本固定安裝至 `~/Applications/Cue.app`，保留既有資料，不需要付費開發者帳號、簽章金鑰或管理者權限。安裝程式不會取代仍在執行的 Cue，也會先驗證暫存的新 App。日後更新原始碼時，先結束 Cue，再執行 `git pull --ff-only` 與 `./scripts/install-app.sh`。若只想使用自己的版本，請關閉自動檢查更新；從 Cue 安裝更新會換成已發布的 App，不會替儲存庫編譯。詳見[原始碼安裝指引](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/building.md)。

App 使用 ad hoc 簽章，**沒有 Developer ID 簽署，也尚未經 Apple 公證**。Sparkle 會驗證更新檔與更新資訊的簽章，但不會取代 Apple 的首次開啟檢查。若遭阻擋，請依[安裝說明](https://github.com/hsiuhsiu/cue/blob/v0.4.0/docs/installation.md)完成針對 Cue 的授權步驟。

驗證包含最佳化的核心、儲存、啟動器、鍵盤、剪貼簿、設定、登入項目、翻譯與系統指令自動檢查，並進行實際啟動器操作。測試使用合成資料與替代系統動作，未實際讓 Mac 睡眠或鎖定。登入註冊與狀態已檢查，但尚未實際登出或重開機驗證自動啟動，也尚未在另一台 Mac 驗證從公開來源更新安裝。鎖定螢幕使用 macOS 私有服務，未來可能需要調整。通用版支援 Apple silicon 與 Intel，最低建置目標為 **macOS 14**；此版本使用 **Xcode 27** 建置，目前只在 **Apple silicon／macOS 27.0** 實際執行測試。
